# ADR-0002: T006 会话状态归属与 S3 生命周期

- 状态：已接受
- 日期：2026-08-02
- 决策者：Trident-Kraken

## 背景

T006 需要补齐 0x10、0x3E、肯定响应抑制和 S3 自动降级。现有 0x10 handler
同时修改会话/安全状态，而设计要求 engine 独占这些状态；T006 的 UT-04 又引用了
尚未进入实现范围的 0x2E。

## 决策

1. 会话和安全状态由 `uds_engine.c` 管理。服务 handler 只校验业务并构造响应；
   handler 成功后由 engine 应用会话副作用，响应发送失败不回滚副作用。
2. 每个成功的 `10 01` 或 `10 03` 都重建目标会话并复位安全状态。默认会话停用
   S3，扩展会话启动或重置 5000ms S3。
3. 通过 validator 的请求定义为有效诊断请求。engine 在安全检查前续期 S3；
   安全拒绝、业务 NRC 和 `3E 80` 仍续期。未知 SID、长度/子功能错误和 TX busy
   请求不续期。
4. 0x2E 端到端验证留在 T008。T006 不增加临时 0x2E stub，只为 S3 逻辑增加不依赖
   0x2E 的测试观察方式；T008 再用 0x2E 完成 UT-04。

## 后果

- engine 与 services 的职责边界和详细设计一致，后续 T007/T008 可以复用统一的
  安全复位和会话检查。
- T006 的自动化测试不提前扩大 UDS 服务范围；UT-04 的最终业务断言由 T008 关闭。
